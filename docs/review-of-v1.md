# Review of v1

**v1:** one script, `sql/ipl_analysis.sql`, written for the 2008–2019 IPL dataset.

**How it was reviewed:**
- The data was loaded into the v1 column layout (`Matches`, `deliveries`, 1-based `overs`).
- The script was run unchanged on MySQL 8.0.
- Each query was then checked against cricket scoring rules.

## Errors when run

| # | Problem | Effect |
|---|---|---|
| 1 | Lines starting with `-----` / `------` used as comments. MySQL only treats `--` *followed by a space* as a comment | **3 statements failed with error 1064**: the `bowler_match_impact` view, the bowling-metrics query and the phase-weighted bowling query. The whole bowling half never ran |
| 2 | `CREATE VIEW` without `OR REPLACE` on 5 views (`ball_by_ball`, `ball_with_phase`, `phase_performance`, `batsman_stats`, `bowler_match_impact`) | The script fails on the second run |

## Wrong numbers

| # | Problem | Fix in v2 |
|---|---|---|
| 3 | Super-over balls (inning 3+) treated as innings | Excluded in `v_ball` (161 deliveries) |
| 4 | Ties and no-results gave `is_winner = 0` to *both* teams, counting as losses | `is_decided` flag. 19 matches excluded from win rates |
| 5 | Balls faced counted wides | `is_faced` excludes wides |
| 6 | Balls bowled counted wides and no-balls | `is_legal` |
| 7 | Bowler economy charged byes and leg-byes to the bowler | `bowler_runs` = batter runs + wides + no-balls |
| 8 | Team run rate divided by all deliveries, including wides and no-balls | Divided by legal balls |
| 9 | Venue names not standardised: Wankhede appeared twice, Chinnaswamy three times, Kotla and Arun Jaitley Stadium separately | `ref_venue`: 58 → 36 grounds |
| 10 | Renamed franchises treated as different teams (Delhi Daredevils / Capitals, Kings XI / Punjab Kings) | `ref_team`: 19 → 15 franchises |

## Weak logic

| # | v1 claim or query | Issue | v2 approach |
|---|---|---|---|
| 11 | "Death overs are the strongest predictor of winning" | Mixed batting-first and chasing innings. A winning chase often ends before the death overs, so winners chasing score **fewer** death runs (34.0 vs 38.5) | Every factor is split by `innings_role` (05 Q1, Q3, Q5) |
| 12 | "Wickets timing impact" | Bucketed *total* wickets lost, which is partly a consequence of losing, and nothing about timing | Wickets in hand after 15 overs (05 Q4): a leading indicator |
| 13 | Venue chase rate | Included rain-adjusted matches and grounds with 2–4 games | D/L excluded, minimum 20 matches, classified Chase / Neutral / Bat first |
| 14 | Bowler impact = 2 × wickets per match + 1.5 × wickets in wins − economy | Always negative (economy dominates), so the score couldn't be read | Economy measured against the league average for the same seasons |
| 15 | Player impact over all seasons, 2008 onwards | Not useful for a current shortlist | Season window in `ref_window` (default 2022–2024) |
| 16 | README figures ("+17% win chance") | Not reproducible from the repo | Every number is in `results/*.csv` and regenerated by `run_all.sql` |

## Kept from v1

- The layered-view design: `ball_by_ball` → `ball_with_phase` → `team_innings` → `match_outcome` became `v_ball` → `v_team_innings`.
- Phase segmentation: Powerplay / Middle / Death.
- Powerplay and death-over run buckets, and the powerplay strategy matrix (strong / aggressive / slow / weak).
- Venue chase win rate.
- The impact-score idea and its weights (0.6 / 0.4 for batters, 2 / 1.5 for bowlers).

## Removed

- `select * from batsman_match_impact limit 10;` (debug output).
- The `batsman_stats` view (created, never used).
- The phase-weighted bowling query: joined deliveries back to a view only to recover the phase, and was never aggregated to bowler level. Death-over bowling is now a column in `v_bowler_impact`.
